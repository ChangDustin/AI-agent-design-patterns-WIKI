## 1. LLM 的提案

### 這篇在講什麼

1. **代理的解剖圖**：LLM 是代理的「大腦」，外加三個元件：
   - **規劃**：拆解子目標，以及反思和修正（對過去的行動自我批評、從錯誤中學習）。
   - **記憶**：短期記憶（in-context learning，也就是放在上下文裡的東西）和長期記憶（外部向量資料庫＋快速檢索，可以存取近乎無限的資訊）。
   - **工具使用**：呼叫外部 API，取得模型權重裡沒有的資訊，例如最新消息、程式執行、私有資料。
2. **規劃怎麼拆任務**：思維鏈（CoT，叫模型「一步一步想」）；思維樹（ToT，每一步產生多個想法，形成一棵樹，再用 BFS／DFS 搜尋）；拆解方式有三種：簡單提示、任務專用的指令（例如「寫故事大綱」）、由人提供。另外 LLM+P 把長程規劃外包給傳統規劃器。
3. **反思**：ReAct（「想 → 做 → 看」的格式反覆循環，比只做不想的版本好；這是我們第 4 篇要讀的論文）；Reflexion（把反思寫進工作記憶，最多留三則；有規則偵測「走太久沒成功」或「重複同一個動作得到同樣結果」，就停下來重來）；另外還有兩個需要訓練模型的方法（Chain of Hindsight、Algorithm Distillation）。
4. **記憶對應人腦**：感覺記憶 ↔ 原始輸入的 embedding；短期／工作記憶 ↔ 上下文，受限於上下文視窗長度；長期記憶 ↔ 外部向量資料庫，查詢時快速檢索（近似最近鄰，例如 LSH、HNSW、FAISS）。
5. **工具使用**：MRKL（LLM 當路由器，把問題轉給專家模組：計算機、匯率、天氣 API……）。實驗發現 LLM 連文字應用題的計算參數都抽不準，所以「知道何時、如何使用工具」才是關鍵。其他還有 Toolformer、ChatGPT Plugins、function calling；HuggingGPT 的四階段（任務規劃 → 選模型 → 執行 → 彙整回應）；API-Bank 評測工具使用的三個層級（會呼叫 → 會找 API → 會規劃多次呼叫）。
6. **案例**：
   - **ChemCrow**（化學代理，13 個專家工具）：用 LLM 評分時，它和 GPT-4 差不多；請化學專家評分時，ChemCrow 遠勝 GPT-4。→ **在專業領域，LLM 不擅長評估自己的結果**。
   - **科學研究代理**：被要求合成已知化學武器時，11 次中有 4 次（36%）接受了。→ 代理有安全風險。
   - **Generative Agents（AI 小鎮）**：25 個由 LLM 控制的虛擬角色生活在類似模擬市民的沙盒裡，靠記憶流、檢索（依新近程度、重要性、相關性）、反思、規劃互動，自然出現資訊傳播、記得人際關係、一起辦派對等社交行為。
   - **AutoGPT**（概念驗證，可靠度問題很多，很多程式碼都在解析輸出格式）、**GPT-Engineer**（寫程式前先問釐清問題）。
7. **三大挑戰**：上下文長度有限；長期規劃與任務拆解很難（遇到意外錯誤時，LLM 很難調整計畫）；自然語言介面不可靠（格式錯誤、偶爾不聽指令，所以示範程式很多在解析輸出）。

**和本專案有關的兩個發現：**

- Weng 說「很多代理程式碼都在解析模型輸出」，這等於預告了我們 pipeline 可能最常出錯的地方：要求 LLM 輸出 JSON。之後實際跑的時候可以拿來對照（只是預測，以實際紀錄為準）。
- GPT-Engineer「寫程式前先問釐清問題」，跟我們 ingest 的「先討論、後生成」是同一個想法。

### 想問作者的問題

1. **反思要放在哪？** 三篇資料的分類都不同。我建議維持「反思」獨立一頁（教學上最清楚），在頁面裡並陳三種分類法。
2. **記憶的比喻**：短期記憶（上下文視窗）＝**書桌桌面**，空間有限；長期記憶（向量資料庫）＝**書櫃**，東西很多，但要先找出來才能放上桌。另外，課程的 RAG（向量資料庫）其實就是長期記憶的一種實作，要不要在記憶頁連到課程的 RAG？（Wiki 目前沒有 RAG 的來源，只能標「Wiki 綜合」）
3. **太深的內容**：Chain of Hindsight、Algorithm Distillation（要微調或強化學習）、MIPS 演算法（LSH、HNSW、FAISS……）對非資工觀眾太深。我建議只在來源頁記一筆，不建概念頁、不進簡報。
4. **要不要建「代理的限制與風險」頁？** 內容整合 Weng 的三大挑戰、ChemCrow 的「LLM 在專業領域評不出自己的錯」、科學代理的安全風險，以及 Anthropic 的「成本高、錯誤會累積」。我認為這頁對教學很重要（讓觀眾知道代理會出包），也會影響我們 pipeline 的檢查設計：不能只靠 LLM 自己審自己。
