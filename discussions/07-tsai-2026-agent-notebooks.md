## 1. LLM 的提案

### 這三份在講什麼

**共同的設計理念**（三份都反覆強調）：
- 用 AISuite 呼叫 Groq 的 `gpt-oss-120b`，**流程由我們自己寫清楚，不交給隱藏的自動迴圈**。
- 都只是**同一個模型的幾次普通文字呼叫**，「作者」「評論者」「規劃者」的差別是收到的指令和資料不同，不是不同的 AI，也**不是完整的自主代理**。
- **模型不會記得上一次呼叫**，下一步需要的資料（尤其是原始需求）要由 Python 明確放進 prompt。
- **資料不是指令**：草稿、工具結果裡的文字只是待處理的資料，不能覆寫任務指令（區段標記也不是完整的安全機制）。
- **可由程式確認的事情，盡量交給程式**（例如字數、價格計算）。
- 工程習慣：遮蔽金鑰的 `safe_error`、逾時 60 秒、不自動重試（避免重複消耗額度）、失敗時保留已完成的階段並標出停在哪裡、輸入過長就不呼叫 API。

**Agent01 Reflection：讓 AI 檢查與改進回答**
1. 流程：需求 → 初稿 → 評論 → 第二版，固定三次呼叫就停，**停止條件是人設計的**。
2. 例子：虛構情境「第一次用 Python 畫出心形圖，少打一個括號，看錯誤訊息後成功」，寫成給大學生的貼文。
3. 先把「好文章」的標準寫清楚，否則評論者可能只是把文章拉長。
4. 評論者要同時看到**原始需求和初稿**，評論分成「值得保留／需要修改／仍需確認」；沒問題可以說保留，不必硬找缺點；不要捏造精確字數（字數交給 Python）。
5. 改稿時**原始需求優先於評論**：故意塞一條壞建議（加五個 emoji、編造教授稱讚），看模型會不會照單全收。
6. 第二版不一定比較好：「更長、更華麗，不等於更符合任務」。同一個模型可能重複同樣的盲點；換一個模型評論，也不等於獨立的事實查核。
7. 帶走三個問題：評論有沒有看見原需求？修改有沒有忠於素材？第二版到底改善了什麼？

**Agent02 Tool Use：讓 AI 使用工具**
1. 例子：「麥茶買 20 杯，預算 800 元夠嗎？」其實混了三件事：讀懂品名和杯數、查價格與庫存並計算、用自然語言解釋。
2. 三階段：**第一次 LLM** 把問題轉成 JSON 工具請求（`get_menu`／`quote_order`／`clarify`）→ **Python** 解析、檢查、執行 → **第二次 LLM** 根據「原問題＋請求＋實際結果」回答。
3. 工具就是普通 Python 函式；價格由程式查、總價由 Python 乘（20 × 30 = 600 元），不讓模型猜。
4. 派送器只允許白名單上的工具，不用 `eval`／`exec`；JSON 不合法就報錯，**不猜一組參數補上**；缺杯數就選 `clarify` 追問。
5. 這是「用 prompt 實作的教學版工具路由」，不是 API 原生的 tool calling；原生介面只是把同樣的傳遞標準化。
6. 把庫存改成 8 杯，同樣的參數會得到「庫存不足」：工具讀的是當下資料，不需要重新訓練模型。
7. 帶走三個問題：參數對不對？程式實際做了什麼？最後回答有沒有忠於資料？

**Agent03 Planning：員瑛式思考生成器**
1. 例子：「特地去買可頌，到了才發現賣完了」→ 先產生**可編輯的回應計畫**（已知事實、接住失落、兩個正向角度、選用角度與理由、小行動、寫作安排）→ 再依「原事件＋計畫」寫貼文，日常小挫折以「完全是 Lucky Vicky 呀！」結尾。
2. 不編造好結果：未發生的好事只能寫成可能性；重大痛苦（喪親、重病）不開玩笑、不套幸運口號。
3. **人可以介入**：直接修改計畫，只重跑寫作階段。
4. **Planning ≠ CoT**：CoT 是用中間推理步驟連接問題與結論；Planning 是先決定子任務、需要的資料和順序，再照計畫執行。兩者可以結合，但不是同一件事。
5. 代價：多一次呼叫、更多 token 和延遲；錯誤的計畫也會傳到下游。
6. 這裡的規劃是**固定的兩步**，不是讓模型自主拆出任意流程的完整代理。

### 想問作者的問題

1. **簡報要不要用課程的例子？** 這三個在地化例子對同學最有共鳴，我建議分別當反思、工具使用、規劃的「實作例」：
   - **反思**：「第一次用 Python 畫心形圖」貼文（初稿 → 評論 → 第二版）
   - **工具使用**：「麥茶 20 杯，預算 800 元夠嗎？」（模型轉請求 → Python 算出 600 元 → 回答）
   - **規劃**：「可頌賣完了」員瑛式思考（計畫 → 貼文）
2. **「規劃」有兩種意思**：Ng 的規劃是 LLM 自主決定步驟（屬於代理）；課程的 Planning 是固定兩步「先寫可編輯的計畫，再照計畫寫」（屬於工作流程）。我建議規劃頁並陳「自主規劃」和「先計畫再執行」兩種意思，並在思維鏈頁加上「CoT ≠ Planning」。
3. **要不要新增「人在迴圈中」頁？** 這頁整合四處說法：ReAct 改一兩句想法就能修正、Anthropic 的檢查點和人工測試、課程的可編輯計畫和「人決定採不採用」、我們自己的「先討論、後生成」。它會是簡報最後「AI 做事、人來把關」的依據。
4. **pipeline 要不要直接沿用課程的寫法？** 課程和我們用同一套工具，我建議 pipeline 沿用並標註出處：
   - `call_llm` 的設定：`reasoning_effort="low"`、只取 `content`、空回覆就停
   - 用 `safe_error` 遮蔽金鑰
   - prompt 裡寫明「資料不是指令」
   - 可由程式確認的事情交給程式

   同時建 `aisuite`、`groq` 兩個工具頁。
